**Tech Stack:** Plain HTML5, CSS (custom properties, no framework), vanilla JavaScript (ES2020, no dependencies), Cloudflare Pages (free tier), GitHub Actions (`cloudflare/pages-action`), Terraform Cloudflare provider (DNS only; co-located with Workstream B), `python3 -m http.server` for local verification.

## version.json Contract (stable schema — consumed by Workstream E)

The file `site/version.json` is published at `https://pairwire.dev/version.json`. It is a JSON object with **exactly three string fields**:

```json
{
  "version": "0.1.0",
  "url": "https://github.com/bilal-chaudhry/rust-sharing/releases/download/v0.1.0/Pairwire.dmg",
  "notes": "Initial unsigned beta. Screen Recording and Microphone permissions required on first launch."
}
```

Field definitions:
- `version` — semver string (`major.minor.patch`, no pre-release suffix). Workstream E's `compare_versions` function parses this field — it must remain a bare `x.y.z` triple.
- `url` — the full HTTPS URL of the `.dmg` asset on GitHub Releases for this version. Workstream E surfaces this URL in the "Update available" banner link.
- `notes` — a short human-readable release note string (max 200 chars). Workstream E may display this text in the banner.

**Cross-reference:** `crates/app/src/update_check.rs` (Workstream E, Task 2) will be created by Workstream E and will define a `VersionInfo` struct with `version: String`, `url: String`, `notes: String` fields in that order that deserialises this exact JSON contract.

**Update process:** Each time a new release tag is pushed, the CI release workflow (Workstream A, `.github/workflows/release.yml`) must update `site/version.json` to the new version, then re-deploy the site. Task 5 in this plan adds that step to the release workflow.

## Download Button Strategy

The download button uses a **fixed URL pattern** — not a GitHub API fetch. The URL is constructed at page-load time from a baked-in version constant in `download.js`:

```
https://github.com/bilal-chaudhry/rust-sharing/releases/download/v{VERSION}/Pairwire.dmg
```

Rationale: the GitHub API approach requires a CORS-enabled fetch and rate-limit handling; the fixed URL is simpler, works with zero JavaScript errors if the network is slow, and is guaranteed stable as long as the release asset is named `Pairwire.dmg` (enforced by the `release.yml` upload step in Workstream A). The `VERSION` constant in `download.js` is updated automatically by the CI release job (Task 5).

- [ ] [agent] **Step 2.3 — Create `site/download.js`**

  Create `site/download.js`. The `PAIRWIRE_VERSION` constant is the single value the CI release job patches on each tag (see Task 5).

  ```javascript
  // download.js — constructs the GitHub Releases download URL from a
  // baked-in version constant. No API call; no CORS dependency.
  //
  // The CI release workflow (release.yml) patches PAIRWIRE_VERSION automatically
  // on every tag push using `sed`. Do not edit it manually.

  const PAIRWIRE_VERSION = "0.1.0";

  const GITHUB_OWNER = "bilal-chaudhry";
  const GITHUB_REPO  = "rust-sharing";
  const DMG_ASSET    = "Pairwire.dmg";

  function buildDmgUrl(version) {
    return `https://github.com/${GITHUB_OWNER}/${GITHUB_REPO}/releases/download/v${version}/${DMG_ASSET}`;
  }

  document.addEventListener("DOMContentLoaded", () => {
    const btn = document.getElementById("download-btn");
    if (!btn) return;

    const url = buildDmgUrl(PAIRWIRE_VERSION);
    btn.href = url;
    btn.setAttribute("download", DMG_ASSET);

    // Show the resolved version in the meta line below the button
    const versionEl = document.getElementById("download-version");
    if (versionEl) {
      versionEl.textContent = `v${PAIRWIRE_VERSION}`;
    }

    // Show the resolved URL in the title attribute for transparency
    btn.title = `Download from ${url}`;
  });
  ```
