## Execution order & dependency graph

```
        ┌──────────────────────────── start in parallel ────────────────────────────┐
        │                              │                              │
   ╔═════════╗                    ╔═════════╗                    ╔═════════╗
   ║    A    ║  FFmpeg spike      ║    B    ║  Rust wiring +      ║    D    ║  telemetry
   ║  (DMG)  ║  FIRST, gates A    ║ (relay) ║  TF authoring       ║ (crate) ║  code
   ╚════╤════╝                    ╚════╤════╝                     ╚═════════╝
        │ produces:                    │ produces:
        │  release.yml, --version,     │  infra/terraform/dns.tf,
        │  Pairwire.dmg URL pattern    │  relay.pairwire.dev
        ▼                              ▼
        └────────────► ╔═════════╗ ◄───┘
                       ║    C    ║  needs A's release.yml + dmg URL, B's dns.tf
                       ║ (site)  ║  produces: /version.json (schema = E's contract)
                       ╚════╤════╝
                            ▼
                       ╔═════════╗  needs C's /version.json contract; threads update_rx
                       ║    E    ║  into A's run_host_with_overlay* fns — run AFTER A
                       ╚═════════╝
```

**Parallel from the start:** A, B (code), D. **Then:** C (after A + B). **Then:** E (after A + C).

**Why these edges (not arbitrary):**
- **C → A:** C's CI deploy reads `.github/workflows/release.yml` (created by A) and links A's `.dmg`. C Task 4/5 have explicit BLOCKED-until guards.
- **C → B:** apex/`www` DNS records co-locate in B's `infra/terraform/dns.tf`. C guards on its existence.
- **E → C:** E parses `/version.json`; the schema (`version`, `url`, `notes`) is defined in C and referenced by E.
- **E → A:** E threads an `update_rx` param into `run_host_with_overlay` / `run_host_with_overlay_and_tray` (the same fns A edits for `--version`). Sequence E after A to avoid churn on `crates/app/src/main.rs`.
- **A internal:** the FFmpeg static-vs-dylibbundler **spike is Task 1** — it gates the bundling form for the rest of A. A `[human]` clean-machine VideoToolbox check records the outcome.

**Isolation:** A and B both touch build config / new top-level dirs heavily — run each in its own git worktree (superpowers:using-git-worktrees) if executing concurrently.
