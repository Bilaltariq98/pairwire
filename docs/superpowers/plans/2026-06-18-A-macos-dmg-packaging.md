# macOS .app + Unsigned DMG Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a self-contained, ad-hoc-codesigned `pairwire.dmg` that a colleague can download, open, grant Screen Recording + Microphone, and immediately start a 1:1 session — with no Homebrew dependency required.

**Architecture:** `cargo-packager` (CrabNebula) produces the `.app` bundle and `.dmg` from a `[package.metadata.packager]` stanza in `crates/app/Cargo.toml`, consuming a pre-built release binary, `Info.plist`, `pairwire.entitlements`, and `pairwire.icns`. FFmpeg linkage is decided by a time-boxed spike (static `CARGO_FEATURE_STATIC` first; fall back to `dylibbundler` + `install_name_tool` rpath rewrite if VideoToolbox breaks under static). The GitHub Actions release workflow triggers on tag push, builds the binary with all production features, runs `cargo packager`, and uploads the `.dmg` to GitHub Releases.

**Tech Stack:** Rust / cargo, cargo-packager 0.11, iconutil (Xcode CLI tools), codesign (Xcode CLI tools), dylibbundler (Homebrew, fallback only), GitHub Actions macOS runner, `just` task runner.

**PLAN.md task ID(s):** P4.5.1 (sub-tasks P4.5.1.1 through P4.5.1.10)

### Task 1: FFmpeg Linkage Spike — Static vs dylibbundler [agent]

Decide the FFmpeg bundling strategy before touching packaging config. This is the highest-risk unknown and gates the final `.app` form.

**Files:**
- Modify: `LEARNINGS.md` (record outcome)
- Modify: `justfile` (add `ffmpeg-spike` recipe)

**Background:** `ffmpeg-next 8` currently links dynamically to system Homebrew FFmpeg via pkg-config. A `.app` on a clean machine has no Homebrew, so FFmpeg `.dylib`s must either be statically compiled in or bundled in `Contents/libs/`. Static linking (`CARGO_FEATURE_STATIC`) would build FFmpeg from source and produce a self-contained binary but may break VideoToolbox (Apple's HW H.264 accelerator) if its `AVVideoToolboxCodecFramework` dynamic framework cannot be found at runtime. The dylibbundler route copies `.dylib` files into the `.app` and rewrites their `@rpath` references with `install_name_tool`.

**Steps:**

- [ ] Add a `ffmpeg-spike` recipe to `justfile` that attempts a static release build. Note: `FFMPEG_DIR` is intentionally left unset (not blanked to `""`) so that `ffmpeg-sys-next`'s static build scripts choose the bundled source — blanking it to `""` would conflict with a developer's existing local FFmpeg environment:

```makefile

# Requires: brew install nasm pkg-config
# If this succeeds and VideoToolbox works in a clean VM → use static.
# If VideoToolbox breaks → use dylibbundler (see Task 4 fallback).
ffmpeg-spike:
    #!/usr/bin/env bash
    set -euo pipefail
    unset FFMPEG_DIR BINDGEN_EXTRA_CLANG_ARGS 2>/dev/null || true

    cargo build -p pairwire \
        --release \
        --features encode,capture,audio,gui,tray \
        2>&1 | tee /tmp/ffmpeg-spike.log
```

```makefile
# Generate a minimal 32×32 RGBA placeholder tray PNG (dark circle on transparent background).
# Replace assets/tray-icon.png with the real 32×32 RGBA design asset before production release.
tray-placeholder:
    #!/usr/bin/env bash
    set -euo pipefail
    python3 - <<'PYEOF'
import struct, zlib

def png_chunk(name: bytes, data: bytes) -> bytes:
    crc = zlib.crc32(name + data) & 0xffffffff
    return struct.pack('>I', len(data)) + name + data + struct.pack('>I', crc)

W, H = 32, 32
cx, cy, r = W // 2, H // 2, 12
raw = b''
for y in range(H):
    raw += b'\x00'  # filter byte: None
    for x in range(W):
        dist2 = (x - cx) ** 2 + (y - cy) ** 2
        if dist2 <= r * r:
            raw += bytes([30, 30, 30, 220])   # dark circle, mostly opaque
        else:
            raw += bytes([0, 0, 0, 0])         # transparent

compressed = zlib.compress(raw)
ihdr = struct.pack('>II', W, H) + bytes([8, 6, 0, 0, 0])  # bit_depth=8, color_type=6 (RGBA)
png  = b'\x89PNG\r\n\x1a\n'
png += png_chunk(b'IHDR', ihdr)
png += png_chunk(b'IDAT', compressed)
png += png_chunk(b'IEND', b'')

with open('assets/tray-icon-placeholder.png', 'wb') as f:
    f.write(png)
print('Written assets/tray-icon-placeholder.png (32x32 RGBA)')
PYEOF
```

```rust
    ///
    /// The asset at `assets/tray-icon.png` (workspace root) is embedded via
    /// `include_bytes!` when the `tray` feature is compiled. The file must exist
    /// at build time — there is no runtime fallback. The placeholder PNG committed
    /// in Task 3 satisfies this until the human provides the real asset.
    fn load_tray_icon() -> anyhow::Result<tray_icon::Icon> {
        use image::GenericImageView as _;
        // CARGO_MANIFEST_DIR for crates/app is the workspace root / crates/app.
        // ../../assets resolves to <workspace-root>/assets/tray-icon.png.
        const TRAY_PNG: &[u8] = include_bytes!(
            concat!(env!("CARGO_MANIFEST_DIR"), "/../../assets/tray-icon.png")
        );
        let img = image::load_from_memory(TRAY_PNG)
            .map_err(|e| anyhow::anyhow!("failed to decode tray-icon.png: {e}"))?
            .into_rgba8();
        let (w, h) = img.dimensions();
        tray_icon::Icon::from_rgba(img.into_raw(), w, h)
            .map_err(|e| anyhow::anyhow!("failed to create tray icon: {e}"))
    }
```

```makefile
    set -euo pipefail
    APP="${APP:-target/release/pairwire.app}"
    BIN="$APP/Contents/MacOS/pairwire"
    LIBS_DIR="$APP/Contents/libs"
    mkdir -p "$LIBS_DIR"
    # dylibbundler 1.0.5 uses short flags: -b (--bundle-deps), -x (--fix-file),
    # -d (--dest-dir), -p (--install-path), -od (--overwrite-dir).
    # Long forms (--bundle-deps, --binary, etc.) are not accepted by 1.0.5.
    dylibbundler \
        -b \
        -x "$BIN" \
        -d "$LIBS_DIR" \
        -p "@executable_path/../libs/" \
        -od
    # Ad-hoc sign each bundled dylib to avoid "mapped file has no cdhash" Gatekeeper error.
    # This error appears when a dylib inside a hardened-runtime .app is unsigned.
    # Bottom-up signing order is mandatory: dylibs first, then the binary, then the .app.
    IDENTITY="${CODESIGN_IDENTITY:--}"
    for dylib in "$LIBS_DIR"/*.dylib; do
        codesign \
            --sign "$IDENTITY" \
            --force \
            "$dylib"
        echo "  signed: $(basename "$dylib")"
    done
    # Re-sign the binary (dylibbundler modifies it, invalidating the prior signature).
    codesign \
        --sign "$IDENTITY" \
        --entitlements packaging/pairwire.entitlements \
        --options runtime \
        --force \
        "$BIN"
    # Re-sign the outer bundle bottom-up (after binary is signed).
    codesign \
        --sign "$IDENTITY" \
        --entitlements packaging/pairwire.entitlements \
        --options runtime \
        --force \
        "$APP"
    echo "dylibs bundled and signed in $LIBS_DIR"
    echo "=== Verify inner binary signing: ==="
    codesign -dv "$BIN" 2>&1 | grep -E "Signature|Identifier|Format"
```

**Note on deviations from original spec (discovered during Task 4 / P4.5.1.4 fix commits):**
1. `APP` path uses `target/release/pairwire.app` — cargo-packager 0.11 actual output path.
2. dylibbundler 1.0.5 requires short flags (`-b`, `-x`, `-d`, `-p`, `-od`); long forms are

3. Re-signing the binary and outer `.app` after dylibbundler (which invalidates signatures)
   is required and was added in the same commit that fixed dylibbundler flags. These steps

```yaml
      - name: Cache cargo registry + build
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/registry/index
            ~/.cargo/registry/cache
            ~/.cargo/git/db
            target
          key: macos-release-cargo-${{ hashFiles('**/Cargo.lock') }}
          restore-keys: macos-release-cargo-
          # Note: the `target` directory can grow to multiple GB. Monitor cache
          # usage in the Actions tab and add a size limit step if costs rise.

      - name: Install FFmpeg
        run: brew install ffmpeg pkg-config

      - name: Set FFmpeg bindgen env
        run: |
          FFMPEG_PREFIX=$(brew --prefix ffmpeg)
          echo "FFMPEG_DIR=${FFMPEG_PREFIX}" >> "$GITHUB_ENV"
          echo "BINDGEN_EXTRA_CLANG_ARGS=-I${FFMPEG_PREFIX}/include" >> "$GITHUB_ENV"
          echo "PKG_CONFIG_PATH=${FFMPEG_PREFIX}/lib/pkgconfig:$(brew --prefix)/lib/pkgconfig" >> "$GITHUB_ENV"

      - name: Install cargo-packager
        run: cargo install cargo-packager --version "0.11" --locked

      - name: Extract version from tag
        id: version
        run: echo "VERSION=${GITHUB_REF_NAME#v}" >> "$GITHUB_OUTPUT"

      - name: Build release binary + produce .app and .dmg
        env:
          CODESIGN_IDENTITY: "-"    # Ad-hoc sign. Change to Developer ID cert name when enrolled.
        run: |
          # IMPORTANT: --features must come before '--' (there is no '--' needed here;
          # features are cargo flags, not binary runtime flags).
          cargo packager \
            --release \
            --formats app,dmg \
            -p pairwire \
            --features encode,capture,audio,gui,tray

      - name: Verify bundle signing (inner binary + outer bundle)
        run: |
          APP="target/release/bundle/macos/pairwire.app"
          plutil -lint "$APP/Contents/Info.plist"
          echo "=== Inner binary codesign ==="
          codesign -dv "$APP/Contents/MacOS/pairwire" 2>&1 | grep -E "Signature|Identifier"
          echo "=== Outer bundle codesign + entitlements ==="
          codesign -d --entitlements - -vvv "$APP" 2>&1
          echo "=== spctl ==="
          spctl --assess --type execute --verbose "$APP" 2>&1 || true
          echo "=== Version check ==="
          "$APP/Contents/MacOS/pairwire" --version

      - name: List produced artifacts
        run: ls -lh target/release/bundle/macos/

      - name: Upload DMG to GitHub Releases
        uses: softprops/action-gh-release@v2
        with:
          files: target/release/bundle/macos/*.dmg
          name: pairwire v${{ steps.version.outputs.VERSION }}
          body: |
            ## pairwire v${{ steps.version.outputs.VERSION }}

            ### macOS Installation (arm64)
            1. Download `pairwire_${{ steps.version.outputs.VERSION }}_aarch64.dmg`
            2. Open the DMG and drag pairwire.app to /Applications
            3. **First launch:** macOS will block the unsigned app. Go to:
               System Settings → Privacy & Security → scroll down → "Open Anyway"
               Enter your admin password when prompted.
            4. Grant Screen Recording and Microphone permissions when macOS asks.

            ### Requirements
            - macOS 12.3 (Monterey) or later
            - Apple Silicon Mac (arm64) — x86_64 (Intel) support is deferred

            ### This build is unsigned (v1 beta)
            Ad-hoc codesigned. No Apple notarization. Gatekeeper "Open Anyway" is required.
            Granted TCC permissions persist across launches once approved.
          draft: false
          prerelease: true   # Mark as pre-release until Developer ID signing is added
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Risk Register

| Risk | Severity | Mitigation |
|---|---|---|
| VideoToolbox breaks under static FFmpeg | High | Task 1 spike confirms before committing; dylibbundler fallback in Task 4 |
| "mapped file has no cdhash" on bundled dylibs | High | Task 4 signs each dylib before signing the outer .app; Task 7 verify-bundle catches it with explicit inner-binary check |
| Malformed Info.plist silently kills process on ScreenCaptureKit call | High | `plutil -lint` in Task 5 and Task 7 verify-bundle gates |
| wgpu requires unsigned-executable-memory entitlement under hardened runtime | Medium | Entitlement is documented as false-by-default with flip instruction in Task 5 |
| `cargo-packager 0.11` `signing-identity` struct syntax not supported | Resolved | Task 6 uses a plain string for the TOML field; shell substitution in `just package` handles env var lookup |
| `--features` after `--` is forwarded to the binary at runtime | Resolved | All cargo invocations in justfile and CI place `--features` before any `--` separator |
| Workspace clippy with `package/feature` form fails at workspace root | Resolved | Task 10 uses `-p pairwire --features encode,...` (not `pairwire/encode,...`) |
| tray icon `include_bytes!` path fails if file missing | Resolved | Placeholder PNG is committed to git in Task 3 before any `cargo check`; build error is immediate if absent |
| `packaging/dmg-background.png` absent causes cargo-packager error | Resolved | Solid-colour placeholder generated and committed in Task 6 setup |
| macOS Sequoia removes Control-click→Open bypass | Known/accepted | Spec documents this; release notes in the GitHub workflow body instruct "Open Anyway" via System Settings |
| arm64-only for v1; Intel Mac users cannot run the DMG | Known/accepted | Noted in release description as deferred; lipo universal binary is a fast-follow |
| CI `softprops/action-gh-release@v2` not pinned to SHA | Known/accepted | Supply-chain risk noted; acceptable for v1 beta. Pin to SHA before public release. |
