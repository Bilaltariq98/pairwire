How Pairwire works

A walkthrough of the QUIC / iroh / moq-lite stack behind peer-to-peer screen sharing — written honestly, for developers who want to see the actual architecture.

01

Two protocols. Neither is right.

For decades, real-time apps have had to pick between TCP and UDP. Screen sharing needs the behaviour of both, at the same time, on one connection.

  • TCP is reliable and ordered — but head-of-line blocked. One lost packet stalls everything behind it. A dropped audio packet shouldn’t freeze the video, but on TCP it does.
  • UDP is fast and independent — but raw. No encryption, no congestion control. Every app reinvents reliability, ordering, and security on top, badly.
  • WebRTC solves P2P media, but drags in SDP negotiation, ICE, DTLS, SRTP, and SCTP. It is shaped for browsers and awkward to embed as a native Rust library.

Pairwire needs reliable keyboard events, lossy-but-fast cursor updates, and prioritized video streams — all on a single connection. QUIC (RFC 9000) is the one transport that does all three: a 1-RTT handshake, independent multiplexed streams, encrypted unreliable datagrams (RFC 9221), mandatory TLS 1.3, and connection migration built in.

One protocol for everything.

02

Three tools. Every feature maps to one.

QUIC gives you exactly three ways to move bytes. Each Pairwire feature picks the one that fits its delivery guarantee — and they all ride a single connection.

QUIC primitive → what Pairwire sends over it
PrimitiveGuaranteeCarries
open_bi() reliable, ordered, bidirectional Control channel — ControlMessage (handshake, sharing, control handoff, drawing, goodbye)
open_uni() reliable, ordered, one-way Media (moq-lite groups) and the input stream — InputMessage (keys, clicks, scroll, clipboard)
send_datagram() unreliable, unordered Cursor presence — CursorUpdate, ~60 Hz, under 50 bytes, drop-and-forget

A missed cursor position isn’t worth a retransmit — by the time it arrived it would already be stale — so cursors go over datagrams. A missed keystroke is unacceptable, so input goes over a reliable stream. Everything shares one QUIC connection, negotiated with the ALPN identifier pairwire/1. There is exactly one iroh Endpoint per process — it binds one UDP socket, and creating a second would break NAT traversal.

03

iroh makes peers find each other.

QUIC moves the bytes once a connection exists. Getting two machines behind home routers to open that connection is the hard part — iroh (by n0) handles discovery, UDP hole-punching, and relay fallback, all in Rust.

The host generates an invite link. The guest calls endpoint.connect() with it, and iroh takes over: it attempts a direct peer-to-peer path first and, when a router won’t cooperate, falls back through a relay. The relay only forwards encrypted packets — it can’t read the traffic. If a direct path opens up later, iroh upgrades to it automatically. 

# The invite link is the whole handshake — no account, no lookup
pairwire://0f02581240ab?relay=euc1.relay.pairwire.dev&token=eyJ…
├── 0f02581240ab   endpoint ID (ed25519 public key, hex)
├── relay=…        relay URL, used only if a direct path fails
└── token=…        short-lived session token (auth)

A QUIC connection is identified by a connection ID, not an IP:port pair, so it survives a network change — Wi-Fi to cellular, say — without a fresh handshake. When a direct hole-punch isn’t possible, the session continues over the relay as end-to-end encrypted ciphertext.

04

Media over QUIC, without head-of-line blocking.

Screen and audio ride moq-lite, a small publish/subscribe model layered on QUIC. It organises media into a four-level hierarchy.

The moq-lite object model
LayerExampleRole
Broadcastpairwire/sessionEverything one host publishes
Trackscreen, audio/hostA named stream, with a priority
Group—A decodable unit — one per QUIC uni stream
Frame—One H.264 frame or a 20 ms Opus packet

The load-bearing decision: each Group maps to exactly one QUIC unidirectional stream, and every keyframe starts a new Group. If a packet inside Group 5 is lost, Group 6 still arrives and starts decoding immediately — its own stream is independent. On TCP, Group 6 would wait behind Group 5’s retransmit. Track priority does the rest: the screen track outranks audio, so under congestion QUIC ships the picture first.

One wrinkle worth naming: moq-lite’s media streams and Pairwire’s own raw streams both call accept_uni() on the same connection, so they would steal each other’s streams. A UniStreamRouter prefixes each raw stream with a one-byte type tag (screen = 0x53, tunnel = 0x4C) and dispatches on it.

Every keyframe is its own QUIC stream.

05

Every message on the wire, typed and versioned.

The protocol types live in one crate and serialize with postcard — compact binary, no field names on the wire, length-prefixed for framing. Three message families map onto the three QUIC primitives. 

// Control stream (bidirectional) — session management
enum ControlMessage {
    Handshake(Handshake),           // version, capabilities, codecs, display info
    ControlRequest(ControlRequest), // guest asks to drive
    ControlGrant(ControlGrant),     // host grants control
    ControlRevoke(ControlRevoke),   // host takes it back
    SetSharing { screen: bool, audio: bool },
    DrawStroke(DrawStroke),         // draw on each other's screen
    Goodbye { reason: String },     // clean disconnect
    HostReady,                      // host is in its accept loop
}

// Input stream (unidirectional, guest → host)
enum InputMessage {
    Key(KeyEvent), Click(MouseClick), Scroll(MouseScroll),
    Move(MouseMove), Clipboard(ClipboardSync),
}

// Datagram (unreliable) — ~60 Hz, serializes to under 50 bytes
struct CursorUpdate {
    peer_id: u16, x: u16, y: u16,
    visible: bool, click_animation: u8,
}

postcard is not self-describing: both peers must agree on the exact type layout, byte for byte. That is why the handshake carries a PROTOCOL_VERSION (currently 1) and why changing any of these types is a breaking change. The handshake also negotiates capabilities and codec lists — H.264, H.265, or AV1 for video; Opus for audio — so each side knows what the other can decode before a single frame is sent.

06

The encoder adapts in real time. No restart.

A quality monitor polls the live QUIC connection stats about once a second and turns them into a small health snapshot — round-trip time and packet loss — that steers the encoder.

Based on that snapshot, the encoder is pushed into a different tier through a watch channel — resolution, frame rate, and keyframe interval change without tearing down and rebuilding the encoder. A little hysteresis (several good samples in a row before stepping back up) keeps it from oscillating on a brief blip. The tiers, as tuned in this build:

Adaptation tiers (defined in code; tuned over time)
NetworkResolutionFPSKeyframe
Good — low loss, low RTT1080p302s
Strained — some loss or high RTT720p155s
Degraded — heavy loss720p154s

Capture and encode don’t run on the async runtime. Screen capture (scap, via ScreenCaptureKit) and H.264 encode (FFmpeg) each run on their own dedicated OS thread, bridged to the tokio runtime by bounded channels — and the bound itself is the backpressure: if the encoder falls behind, the newest frame replaces the oldest rather than piling up latency. scap also captures at native Retina resolution, so the encoder is initialised from the first real frame’s dimensions, not from a guess in the config.

07

What’s honest about this.

This is an experiment. It’s rough and unsigned and may break — but the architecture underneath is real, not a demo.

  • One host, one guest, today. Multi-party (a star fan-out over moq-lite broadcasts) and localhost tunneling fit this same stack — they’re designed for, not built yet.
  • Unsigned macOS beta. Gatekeeper will warn you. That’s the deal for now; the first-launch steps are on the home page.
  • Nothing in the media path. No accounts, no server between you and your peer. Screen and audio are end-to-end encrypted and never stored; the relay that carries the minority of connections that can’t punch through NAT sees only ciphertext.
  • The foundation is serious. iroh is maintained by n0, moq-lite tracks the IETF Media-over-QUIC work, and QUIC itself is RFC 9000. It’s a small app on a real stack.
